# Changelog

## Unreleased

- Standard, AgX, Filmic, Raw, and False Color now use Blender 5.2.2's OCIO view transforms on the sRGB display, with the LUTs vendored from Blender 5.2.2 under `crates/potter-core/src/color/luts` (about 6.8 MB). They replace the earlier AgX and Filmic fits; the AgX fit rendered about 0.58 for linear 0.05 where Blender gives 0.23. Potter applies the view curve, then exposure, then the view transform, and gamma on the sRGB-encoded value, as Blender does (`colormanagement.cc`, `libocio_display_processor.cc`). Raw has no display encode, and gamma still applies to it. Looks other than `none` and displays other than sRGB are refused with `UNSUPPORTED_FEATURE`. Pending in a follow-up PR (colour-management looks and curves): the AgX and Filmic looks, which run in the AgX Log and Filmic Log process spaces and need Blender's luminance-compensation LUT and the ACES leg, stay `UNSUPPORTED_FEATURE`; view curves import only as control points, since Bezier handles and extrapolation are not imported yet.
- View transforms run in float32 with OCIO's fast `log2`, `exp2`, and `pow` approximations, the operation order of Blender 5.2.2's default CPU processor. On macOS arm64 they match Blender's default output to within a per-view float bound (2.5e-6 for AgX, 1e-6 for Standard, Filmic, and Raw, 3e-3 for False Color's palette step) and to within one 8-bit step. The match is bounded, not bit-exact: fused versus unfused rounding of the scalar paths can differ on other platforms, and the bound is checked by the Blender oracle test in CI.
- glTF import tags an image used as data (the metallic-roughness, normal, or occlusion texture of a material a primitive references) `NonColor`, as Blender's importer sets `is_data`, so its values are read raw. Before, every glTF image imported sRGB, which decoded packed metallic-roughness and normal data to the wrong values. An image that is both a colour and a data texture is `NonColor` everywhere, as Blender's shared image is.
- glTF import of a packed `metallicRoughnessTexture` now reads it as Blender's importer does: Green is roughness and Blue is metallic, through a Separate Color node in the material graph. Before, the texture filled both native metallic and roughness fields, which read only its Red channel, so imported PBR materials sampled the wrong channels. Such materials now import with a graph, the same as materials with transformed or emissive textures. A glTF material without `metallicFactor` now imports with metallic 1.0, as glTF specifies; it was 0.0. A VRM 0.x `_MainTex` transform now replaces the base color texture's own `KHR_texture_transform` at import, as the VRM Add-on does, and reports the replaced transform as `vrm.mtoon._MainTex`. A scale whose magnitude is below `f64::EPSILON` is 1, as in the add-on.
- `uv.unwrap` with `method: "box"` (the default) and `"cube"` now computes Blender 5.2.2's cube projection (`uv.cube_project` with `cube_size` unset): the centre and cube size come from the bounds of the selected faces, each face projects onto the two axes its normal dominates, and UVs land in [0, 1] rather than the raw `[-1, 1]` of the old per-face projection. Values are stored in Potter's V-down convention. Blender's per-face aspect correction (`correct_aspect`, on by default) needs the material's image and is not applied by `uv.unwrap`. `smart` is unchanged.
- Blender `.blend` import and export use native `shade_smooth`, `sharp`, `seam`, and per-corner `custom_normal` status instead of live `blender_polygon_smooth` / `blender_edge_flags` arrays. Named POINT/CORNER color layers and representable generic attributes are native mesh values; linear RGBA floats are not clamped, BYTE_COLOR encoding and color-layer order/active/render names are metadata. glTF/GLB/VRM write ordered `COLOR_n` data and resolve representable material vertex-color reads; other formats report unrepresented color/generic data as losses honored by `--allow-lossy`. Native material TextureRef fields export as Blender Image Texture / UV Map nodes.
- Scene JSON moves to `schema_version` 4 from version 3: version 3 documents upgrade on load with no data change. A node may carry an optional captured Blender `matrix_basis` (with a fingerprint of its transform), which rig evaluation and `.blend` export use while the fingerprint matches; a stale capture is ignored. Historical blobs are digest-checked before in-memory upgrade and are never rewritten; saves write schema version 4.
- Scene JSON moves to `schema_version` 3 from version 2: version 2 documents are upgraded on load for native shading, named linear color layers, and representable generic element attributes. Historical blobs are digest-checked before in-memory upgrade and are never rewritten; saves write schema version 3.
- Mesh-rebuilding modifiers carry native shading (`shade_smooth`, `sharp`, `seam`) and one authoritative `custom_normal` code state with Blender's 16-bit fan-space pairs, Auto/code0 status, and optional loop-reference order. Render/export vectors are derived at the current fan basis; geometry deformation preserves codes and topology changes transport or re-encode them through the shared Blender setter.
- Material slots resolve once at evaluation: each slot follows its OBJECT or DATA link as Blender's `BKE_object_material_get_eval` does, and Boolean TRANSFER pools the mesh's DATA slots. Applying a modifier writes the evaluated material array to the mesh DATA table and resizes object slots to match, new slots linked to DATA.
- Out-of-range face material indices are legal, as in Blender 5.2.2: they are kept, and the evaluated table resolves them to its last slot for render, glTF and VRM. Validation no longer reports them. FBX writes them as the first exported material, as Blender's FBX exporter does, instead of refusing the mesh. `node.join` clamps a source face to the source's last slot before remapping, as Blender's join does. A materialless glTF primitive without `COLOR_0` binds an empty slot, and mesh slots are created only when a primitive has a material, a material variant, or `COLOR_0`; a `COLOR_0` primitive uses a `DefaultMaterial` slot. A primitive with variant mappings never shares a slot with another primitive, as Blender's importer does.
- A Boolean quick UNION with an empty subject takes the operand mesh's own DATA slots rather than its OBJECT-resolved ones, and apply resizes object slots to that count, as Blender 5.2.2 does.
- Remesh now follows Blender 5.2.2 across BLOCKS, SMOOTH, SHARP, and VOXEL: sparse DualCon octree ring patching and in-octree component flood fill match open, non-manifold, mixed, disconnected, and closed geometry; VOXEL matches OpenVDB 13.0.0 at adaptivity 0 and 0.05–1. Empty evaluated meshes pass through inspect, modifier stacks, persistence, preview/render, and legal export/import. DualCon guards combined arena and output work with a finite allocation budget and returns `LIMIT_EXCEEDED` before excessive allocation.
- Modifier evaluator defaults now come from the Blender 5.2.2 parameter table, including Volume-object runtime defaults; operation validation uses that table instead of hand-written property whitelists. Empty UV-layer selectors resolve to the active imported layer. Cast follows Blender's auto size: radius 0 is unbounded, size 0 uses the mean vertex distance (10 for all-zero geometry), and `use_radius_as_size` selects the radius; the default Cast evaluates instead of being refused. Updating only the display flags of a physics or particle modifier keeps its linked settings. A null required reference (for example `target` or `object`) is refused, leaving the batch uncommitted, while optional null references stay accepted. The regression suite checks every recorded runtime default against Blender 5.2.2 and compares explicit activated/inert behavior scenarios with Blender: edge split, triangulation, solidify, decimation, the default screw angle, array fit length under FIXED_COUNT, the mesh-only spline flag, and Cast (default, cylinder, cuboid, and radius/size paths). Solidify NON_MANIFOLD and Decimate ratio 0.5 remain measured gaps owned by D and PR15; other unlisted audit parameters are explicitly unexercised in the diagnostic inventory.
- **Breaking: native multiple UV layers.** Meshes store UV layers in one `uv_layers` attribute: ordered named layers with `active` (the `uv.*` edit target) and `render` (the render and export default), up to 8 per mesh, as in Blender. `uv_map` and `blender_uv_layers` are gone. Scene JSON moves to `schema_version` 2; version 1 documents are upgraded on load (`uv_map` becomes the render layer, `blender_uv_layers` become the other layers, V flipped to glTF's convention), and saves write version 2 only. Texture references change from `uv_map` to `uv_layer` (`null` = render layer; the old `"uv_map"` value maps to `null`). A reference to a missing layer falls back to the render layer and is reported as `uv.layer_missing`.
- New ops `uv.layer_create`, `uv.layer_delete` (refused with `uv.layer_in_use` while a texture or modifier names the layer), `uv.layer_rename` (updates references; refuses `uv.layer_exists`), `uv.layer_set_active`, and `uv.layer_set_render`. `uv.unwrap`, `uv.transform`, `uv.pin`, `uv.pack`, and `paint.texture` take `uv_layer`. `uv.pack` margin default is Blender's 0.001 (was 0.0 at runtime and 0.04 in the schema). Modifier `uv_layer` defaults to the active layer (Blender's behavior); a named layer that does not exist is `modifier.uv_layer_missing`.
- glTF writes `TEXCOORD_k` for every layer (up to 8) and each material's `texCoord` names its layer, as Blender's exporter does; glTF import reads every `TEXCOORD_n` as `UVMap` / `UVMap.00n`. The glTF `texCoord` restriction (`material.texture_uv_set`) and the `material.texture_uv_map` rejection are removed.
- `.blend` import and export carry every UV layer with its name, order, and active and render indices. OBJ and PLY write the active layer (other layers are `mesh.uv_layer` losses); STL writes no UVs (`mesh.uv_layer` loss). USD writes all layers (`primvars:st` for the render layer) and no longer fabricates UVs. FBX writes `LayerElementUV` per layer and reads them back. Alembic writes and reads one vector GeomParam per layer.
- `.blend` export writes each material's texture fields (base color, roughness, metallic, and normal) as Image Texture nodes that read their own UV layer and keep their image colorspace; a normal texture drives a Normal Map node. An authored shader graph is copied and the fields are overlaid on its Principled BSDF, and the source document is unchanged. A texture field that cannot be written (the active output is not driven by a Principled BSDF, or a normal texture meets a linked Normal input) is reported as `material.shader_graph.material_textures`, and export requires `--allow-lossy` for it.
- Unpacked `.blend` export copies each linked image's source file to a sidecar directory named after the output (`<stem>_assets/`) and points the Blender image at that copy, so a reopened image loads from the sidecar.
- Collection instances retain each member's data and use one slot table (`Snapshot.slot_bindings`) with the source render UV index, UV availability and coverage, material, and joined color-layer metadata per slot. Recursive joins preserve source-face UV coverage separately from synthesized canonical `[0, 1]` rows. Preview/render default selectors use each member's render layer; an explicitly named layer missing on that member falls back to its render layer with `uv.layer_missing`. glTF/GLB/VRM emit primitives per used slot and material variants when shared materials resolve to different `TEXCOORD_n` indices. Named UV layers join in first-seen union order; absent member rows use canonical `[0, 1]` and do not become available source data. Native color layers union by name and preserve layer order/designation; POINT/CORNER conflicts expand to CORNER, missing member colors join as transparent black, and any FLOAT_COLOR source promotes joined encoding. Members join on modifier provenance rules, preserving seam/vertex groups/shading/material slots; mirrored members reverse winding and per-corner data, out-of-range face slots clamp to each member's last slot, and `potter.*` bookkeeping keys are ignored. Conflicting custom properties fail only their owning instance. `.blend` export writes current custom normals/smooth flags; modifiers remap named attributes to new element IDs.
- Boolean defaults to Blender 5.2's EXACT solver (Mesh Arrangements, ported under `crates/potter-core/src/geom/boolean/`). `solver`, `operation`, `operand_type`, `use_self`, `use_hole_tolerant`, and `material_mode` (INDEX or TRANSFER) follow Blender. An object or collection operand is one N-ary call over the subject and every member, so `INTERSECT` with a collection is `A ∩ C1 ∩ C2` rather than `A ∩ (C1 ∪ C2)`. TRANSFER keeps empty slots as `null` material slots. Open operands and results that are not PWN use Blender's non-PWN ray fallback. An unset `object` is a no-op on EXACT, and a collection holding the Boolean's own object is not a dependency cycle. `solver: MANIFOLD` is refused with `modifier.boolean.solver_manifold`. `solver: FLOAT` ports Blender's float32 BMesh intersection solver (`geom/boolean/float.rs`) with `double_threshold` (FLOAT-only), per-operand face flips from the subject and operand transforms, and INDEX material remaps against the subject's effective (OBJECT-resolved) slots. Collection `INTERSECT` and empty collections are refused for FLOAT, as in Blender. Boolean output may be followed by topology-dependent modifiers on every solver; the former `modifier.boolean.downstream_topology` refusal is removed.
- Modifiers have Blender's `show_viewport` and `show_render` flags beside the global `enabled` switch. `modifier.create` and `modifier.update` accept them. Previews, `inspect`, `apply`, OBJ, glTF/GLB, VRM and FBX use the viewport stack; saved renders, `bake`, PLY, STL, USD and Alembic use the render stack. BLEND preserves the stack and flags; BVH does not evaluate modifiers. SVG/PDF have no Blender writer and use the render stack. `pick` evaluates the purpose its render manifest recorded, and saved render manifests record `visibility`. Source data keeps every flag; default-true visibility flags are omitted from serialized documents to preserve existing project/history hashes, while `inspect` reports both explicitly. Breaking: `modifier.apply` now applies only the selected modifier to base data and removes only that modifier; all other modifiers remain in stack order with their flags, matching Blender. `EvaluationContext` and `Snapshot` carry a `purpose` (`preview` by default), and the render path's `render_visibility` argument is gone.
- Modifier apply resolves transform-only object references from world transforms without evaluating unrelated geometry; true geometry operands use their own viewport-active stacks. Array `FIT_CURVE` measures the referenced Curve Data-Block path under its world transform.
- Breaking: `.blend` import keeps `show_viewport` and `show_render` separately; a modifier hidden in only one of them used to import as `enabled: false`. Export folds the global `enabled` into both Blender flags.
- `use_pin_to_last` moves the modifier as Blender 5.2.2 does: a new modifier is inserted before the trailing pinned block, and setting or clearing the pin moves it at once (pinned modifiers take the end of the stack, so noncommutative stacks reorder). Hook and original-data types (multires, soft body) insert before the first non-deform modifier. `modifier.reorder` refuses (`INVALID_OPERATION`) a move that the pin or original-data rules stop short of the requested index, instead of moving partway.
- glTF, GLB, VRM 1.0 and VRM 0.x export convert node-graph materials (imported from `.blend` or authored with node ops) through one resolver (`exchange/material_surface.rs`) that follows Blender 5.2's glTF exporter: Principled BSDF inputs (alpha, emission, transmission, IOR, clearcoat, sheen, specular, anisotropy), image textures with UV map and Mapping (`KHR_texture_transform`), Normal Map, Separate Color and multiply-Mix packing into metallic-roughness and occlusion (also for separate metallic and roughness images), Emission and Add Shader, Background as `KHR_materials_unlit`, and alpha from `Mix(Fac, Transparent)` and clip patterns. Custom graphs export with `material.shader_graph.*` losses for parts glTF cannot express; invalid graphs are errors. Materials no node references never block export. Documented divergences from Blender are listed in `docs/spec.md` (Mix alpha, Background strength, sheen weight, Mix with emission).
- Non-VRM glTF now writes `alphaMode` and `alphaCutoff` (previously only VRM did), so blend and clip materials keep their alpha mode in GLB and glTF. `KHR_materials_emissive_strength` is written only when a channel exceeds 1, and `KHR_materials_ior` only with transmission or specular (the default Potter IOR no longer appears on every material). Textures with a transform list `KHR_texture_transform` in `extensionsRequired`.
- Samplers follow Blender: Linear uses LINEAR_MIPMAP_LINEAR and Closest uses NEAREST_MIPMAP_NEAREST minification; wrap modes map Repeat, Clamp to edge, and Mirrored repeat.
- Textures are packed per glTF channel: any R/G/B/A channel from any image (previously only single-channel G/B masks), with derived PNGs written from raw encoded values. Separate metallic and roughness textures pack into one metallic-roughness texture instead of being refused.
- Blender-imported meshes export UV layers (`uv_layers`, flipped to glTF's V convention), smoothing (`blender_polygon_smooth`), and sharp edges (`blender_edge_flags`) instead of being refused; selection, cached topology and `sharp_face` are not written. Smooth-shaded `.blend` meshes previously exported flat normals silently.
- MToon v0 writes `_EmissionMap` and `_BumpScale` from the material; MToon rejects unlit, clearcoat, sheen, specular, and anisotropy surfaces with `vrm.mtoon_<name>`.
- Mesh-rebuilding modifiers carry shading (`shade_smooth`, `sharp`, `custom_normal`, `blender_polygon_smooth`, `blender_edge_flags.sharp`) with Blender 5.2.2 semantics, checked by `shading_oracle` against Blender-generated fixtures in `tests/fixtures/pr4_shading/`. Mirror averages seam custom normals per smooth fan; Array and Mirror give a merged edge its first source's flags; Subdivision sharpens non-manifold edges (left by coincident mirror faces) as OpenSubdiv does; Triangulate, Solidify, Weld (ALL and CONNECTED), Wireframe, Edge Split (`use_edge_angle`, `split_angle`), Screw, Skin, Decimate, Mask, Build, voxel Remesh and Bevel (smooth flags, strip and corner winding, `mark_sharp` and `harden_normals` for one segment on edges) follow Blender's rules. Bevel recomputes custom normals, so input custom normals there report `modifier.attribute_dropped`.
- Triangulate honours `quad_method`, `ngon_method` and `min_vertices` (defaults SHORTEST_DIAGONAL, BEAUTY and 4) with Blender's BMesh diagonal, beautify and output-order rules, and faces with fewer corners than `min_vertices` stay whole; it previously ignored all three. With `keep_custom_normals` on a mesh without custom normals, the triangles keep the pre-split corner normals, as Blender does.
- Removed the shading refusal on meshes whose modifiers change faces: glTF, GLB and VRM export, collection instances, and `modifier.apply` no longer refuse shading attributes there.
- User-visible winding fix: Screw, Skin and voxel Remesh emitted faces wound opposite to Blender, which flipped their normals and backface culling. Closed screws (a full turn, at least three steps, zero offset) now close as Blender does, using float32 tolerances, so their geometry changes where it previously stayed open. Screw also honours `use_normal_flip`, which was ignored.
- Custom normals follow Blender's setter: a corner without a custom normal takes its computed normal, and a fan whose corners disagree is cut, so the edge between them becomes sharp. A face whose corners all keep the computed normal stores no custom normal, so later deform modifiers keep moving its shading; in a face that also has custom corners, the computed corners are stored as their fan normal.
- Breaking: three settings that were ignored before now fail with `UnsupportedFeature` where Blender acts: `modifier.mirror.bisect` (Mirror `use_bisect_axis` on a mirrored axis), `modifier.bevel.mark_seam` (Bevel `mark_seam` on a mesh with seam edges), and `modifier.bevel.shading_segments` (Bevel `harden_normals`, or `mark_sharp` on sharp edges, with more than one segment or `affect` VERTICES). These settings were ignored before, so scenes that use them now fail instead of evaluating.
- Documented differences not refused: EXACT Boolean results match Blender's face topology on the Blender-generated parity corpus (ring order, face sizes, materials, `fid`, and custom-normal presence exactly; coordinates and UVs within 1e-5); topology outside that corpus is not verified. `solver: FLOAT` topology is not yet gated against Blender's FLOAT output. Bevel `harden_normals` on the one-segment cube differs from Blender by 3e-4 on four corners (tolerance 2e-4), tracked for the bevel-parity PR (PR14).
- VRM import degrades per component: an optional part that is not representable (first person, look-at, one expression, one spring chain, collider or collider group, one MToon material) is dropped alone with its own `vrm.*` loss, and the rest of the avatar imports. Only meta, armature and humanoid are required; when one fails the avatar is dropped with a loss naming it.
- glTF and VRM texture graphs: a `KHR_texture_transform` on any glTF slot, an emissive or occlusion texture, or a `normalTexture.scale` other than 1 imports as a material shader graph, as Blender's glTF importer builds it: Image Texture, Mapping, Texture Coordinate, the Principled BSDF, Normal Map Strength, and the `glTF Material Output` group for occlusion. Emissive and occlusion textures import without a loss, and the graph exports back. VRM 0.x `_MainTex` and `_MainTex_ST` transforms become the same base color graph.
- VRM 1.0 MToon texture slots keep their `KHR_texture_transform` (`avatar.mtoon.<material>.texture_transforms`) and export it back; VRM 0.x export refuses a non-identity one (`vrm.v0.mtoon_texture_transform`).
- glTF import no longer silently drops a `KHR_texture_transform` on any texture slot, and no longer reports emissive or occlusion textures as a loss. A non-default `occlusionTexture.strength` is reported as `material.occlusion_strength` (occlusion is applied at full strength).
- The VRM add-on test harnesses no longer fail under parallel tests. Concurrent Blender installs can exit 0 without printing `STATUS Installed "vrm"` while the add-on tree is complete, so success is the installed tree and a Blender `ERROR` line is the failure; concurrent first downloads of the add-on zip each write their own temp file before the rename.
- glTF append now remaps graph IDs and Image Texture image references, so appended materials keep their own graphs and images. VRM color expressions are validated after MToon settings, preserving binds to shade/rim colors. Texture UV sets select their layer, and a `KHR_texture_transform` `texCoord` override applies to its texture; sets past the layer limit report `mesh.uv_layer` instead of failing. Separate Color in a non-RGB mode reports `UnsupportedFeature`.
- The native shader evaluator supports Separate Color (`ShaderNodeSeparateColor`), so graphs with separated channels render.
- `pot import --format vrm` (VRM 1.0, `VRMC_vrm`) and `--format vrm0` (VRM 0.x, `VRM`) import avatars from `.vrm` files. Potter exports re-import without losses: meta, humanoid, expressions, first person, look-at, spring bones and collider groups, and MToon restore exactly, and re-export to the same glTF JSON within f32 frame tolerance. VRM 0.x name, license URL, copyright, collider-group names and chain joints ride in root `extras.potter` (`avatar_meta`, `vrm0SpringBone`), which VRM readers ignore. Unsupported glTF extensions and VRM features are reported as `vrm.*` losses and need `--allow-lossy`.
- VRM 0.x import now converts bone-parented node transforms into the imported bone's rest frame, preserving accessory positions and rotations (for example, hats and ribbons) instead of placing them in the wrong direction.
- VRM import append policy: `--mode append` (default) attaches the imported avatar only when the scene has no avatar and no imported node, data-block, material or image ID already exists; otherwise it reports `vrm.avatar`. `--mode replace` always attaches it.
- Behavior change (generic glTF/GLB): a node without `extras.potter.id` takes its glTF name as its Potter ID, sanitized to `[a-z0-9_-]` (lowercased, a `node<index>_` prefix when it does not start with a letter, truncated to 64 characters). Duplicates take `_<n>` with `n` the node's index, so IDs are deterministic. Unnamed nodes import as `node`. Files that relied on the old `node` / `node_<n>` IDs for named nodes now import with their names.
- Potter glTF/VRM import restores an MToon material's `ior` from `extras.potter.ior` when `KHR_materials_ior` is omitted (VRM exports omit it for MToon), and VRM 0.x channel-remapped texture copies import under their source image name instead of `<name>_channel_<n>`.
- `pot schema --kind formats` lists `vrm` and `vrm0` as importable, with the import loss conditions.
- glTF / GLB / VRM import groups skins into armatures as Blender's importer does: a skin's armature is the deepest common ancestor of its joints (or that node's parent when it is a joint), so skins of separate characters under a shared empty stay separate, and skins that share a joint tree share one armature holding the union of their joints. Multi-mesh avatars no longer leave unused armature Data-Blocks.
- VRM 0.x spring bone groups start one chain per root bone that is not nested under another listed root, so VRoid hair groups import every root (they used to keep only the first). Writers that list every bone of one chain still import one chain.
- VRM import tolerates f32 rounding in spring radius frames (uniform within 1e-4 relative, with the exporter's shared uniform-scale check), so Blender-written and Potter-written avatars with tilted spring bones re-import without `vrm.spring.*` losses.
- VRM import no longer fails on an out-of-range MToon color: a component outside 0 to 1 is clamped and reported as `vrm.mtoon.<field>`, and the rest of the avatar imports.
- VRM 0.x texture-named vectors (`_MainTex`, `_UvAnimMaskTexture`, and other texture properties) that are `[0, 0, 1, 1]` import without a loss, as the VRM Add-on writes them; a transformed texture is reported as `vrm.mtoon.<name>`.
- A mesh whose `extras.potter.vertex_ids` no longer match its vertices (another tool edited the file, such as the VRM Add-on round trip) imports as third-party glTF with a `mesh.vertex_ids` loss, instead of failing the import.
- Morph NORMAL deltas map through the baked scale as normals do, so VRM 1.0 avatars with a non-uniformly scaled mesh and shape keys re-import without `mesh.morph_normals`.
- Decimate COLLAPSE now follows Blender 5.2.2's `bmesh_decimate_collapse` on a BMesh-shaped topology (heap tie order, float32 costs, disk and radial order, symmetry pairing, the triangulate-then-join steps, and loop UV interpolation), so output positions, face rings, UVs and vertex-group weights match Blender vertex for vertex for every ratio, symmetry axis, triangulation option, and vertex-group setting (`vertex_group`, `invert_vertex_group`, `vertex_group_factor`). Output changes for COLLAPSE meshes whose collapse order or positions differed from Blender before. Inverted vertex-group COLLAPSE is supported; `modifier.decimate.collapse_vertex_group_invert` is removed from the feature catalog.
- Decimate UNSUBDIV and DISSOLVE follow Blender's BMesh algorithms for the oracle set (iterations 1 to 3, every delimit mode, boundaries, and fully dissolved meshes, which keep Blender's loose vertices and wire edges instead of faces).
- Decimate COLLAPSE on a 100k-triangle grid at ratio 0.1 takes 0.26 s in release on this machine versus 0.30 s for Blender 5.2.2 (best of three; both produce 9,945 faces).
- Decimate COLLAPSE interpolates POINT and EDGE custom data at each edge collapse like Blender: INT values round per step, BOOLEAN values OR positive-weight sources, FLOAT / FLOAT_COLOR values blend linearly, and BYTE_COLOR values blend as Blender's stored bytes (sRGB RGB, linear alpha) and round at every collapse, so a black/white midpoint is byte 128; new BYTE_COLOR values default to white. Native `seam`/`sharp` and `blender_edge_flags` are read and written with Blender's COLLAPSE edge-splice rules.
- Decimate DISSOLVE reuses freed loop records when it joins faces. A 49,999-quad tied-cost strip (100,000 vertices, `angle_limit` π, joins that grow one face) peaks at 76 MB instead of retaining every intermediate face ring (about 2.5 billion loop records, roughly 70 GB projected). That run takes about 425 s of CPU (about 17 minutes wall on this loaded machine), because joins still recompute each grown face's normal and walk its ring. DISSOLVE reads native `seam`/`sharp` edge attributes and writes them back; flags come from the surviving edge.
- glTF, GLB and VRM exports from Potter also store `extras.potter.polygons`: each face's corners (quads, n-gons, triangles), its primitive, its smooth flag, and the sharp edges, packed into binary buffer views rather than JSON. Import restores face order, corner order, materials, UVs, `shade_smooth` and `sharp` from them, so Potter quad meshes round-trip exactly and no longer report `mesh.morph_normals` because export triangulated them; the primitives still hold triangles for other readers. A 300×300 grid (90,000 quads) stores its record in 1.98 MB instead of 5.02 MB of JSON, and its GLB is about 15% smaller. Third-party glTF keeps the triangle import and its losses. Structurally malformed records fail the import; a well-formed record that does not match its triangles, or an unknown `version`, imports triangles and reports `mesh.polygon_topology`.
- Alembic files use Blender's Y-up basis: points, normals and local transforms are stored as `(x, z, -y)` and polygon winding is reversed, so Blender imports Potter's `.abc` at the placement and facing Blender gives the same scene. Potter reads every `.abc` with this basis, so `.abc` files written before this change import rotated, and mesh cache modifiers that point at them (breaking). Re-export those files.
